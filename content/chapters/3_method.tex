\section{Method}
\label{sec:method}

This section describes our evaluation framework for transferring frozen V-JEPA 2.1 image-spatial and video-spatiotemporal features to aerial metric depth estimation and semantic scene completion (SSC).  The method starting is intentionally organized as a sequence of probes followed by progressively more structured decoders for evaluating dense feature transfer in both rgb and video variants of V-JEPA 2.1 for aerial MDE, with aim to select the best performer and compare with Occufly dataset Finetuned DAV2 MDE. Decoupled Geometric and Image context layers style SSC paradigm is chosen, specifically CGFormer and FoundationSSC inspired variants as they structurally allow for controlled evaluation on geometric and image context feature contribution for SSC. 

We evaluate if and how far previously selected learned MDE heads, a learnable pose aware Multi View Stereo Depth Estimation head and a learnable image context feature represenattion head with their backbone as frozen V-JEPA 2.1, benifit in improving aerial SSC. Knowing that existing metric MDE models are not generalisable we leverage the fact that UAV pose/altitude and onboard camera intrinsics are usually known or estimated using auxilary systems and evaluate benifits of Feature wise learning based modulation (FiLM) for aerial MDE and indirectly SSC. 

We mathematically formulate the train/eval/test data source, problem statement for MDE and SSC. Followed by description of the adapter/neck needed to make V-JEPA 2.1 features usable by the downstream heads. Then progressively dive deeper into considered MDE heads and SSC variants related sourcing, compatability details followed by answering a questionair that answers what componet or componet combination has helped to benifit aerial SSC?? This direction of flow is summarized in \cref{fig:evaluation_overview}.
The following sections outline the evaluation framework, metrics, and experiments conducted. Later the same structure will be used to report results obtained.

\subsection{Problem Formulation and Notation}
\label{sec:method_problem}

We use Occufly dataset~\cite{gross2026occufly} for all experiments.  The per sample data details used from the dataset is mathematically formulated as follows.
\begin{equation}
    s_t = \left(I_t, D_t, M_t, Y_t, K_t, h_t, T_t^{w\rightarrow c}\right),
\end{equation}
where $I_t \in \mathbb{R}^{3\times H\times W}$ is an RGB frame, $D_t$ is a metric depth map, $M_t \in \{0,1\}^{H\times W}$ is the valid-depth mask, $Y_t$ is the semantic occupancy grid, $K_t$ is the camera intrinsic matrix, $h_t$ is the UAV altitude, and $T_t^{w\rightarrow c}\in\mathbb{R}^{4\times4}$ is the world-to-camera pose.
The leading dimension 3 in $I_t$ denotes RGB color channels, $H\times W$ denotes the image resolution before the V-JEPA 2.1 resize, and the $4\times4$ pose matrix is a homogeneous rigid transform.


The monocular depth, multiview depth, and SSC task functions are
\begin{equation}
    \begin{aligned}
    f_D^{\theta_D}&: (I_t,K_t,h_t) \mapsto \hat{D}_t,\\
    f_{D,\mathrm{MVS}}^{\theta_M}&: (\mathcal{V}_t,h_t)
        \mapsto (\hat{D}_t^{\mathrm{MVS}},P_t^{D,\mathrm{MVS}}),\\
    f_S^{\theta_S}&: (\Phi_t, K_t, h_t, \hat{D}_t, P_t^D) \mapsto \hat{Y}_t.
    \end{aligned}
    \label{eq:task_functions}
\end{equation}
Here $f_D^{\theta_D}$ denotes the monocular depth-estimation model with trainable depth parameters $\theta_D$, and $f_{D,\mathrm{MVS}}^{\theta_M}$ denotes the learnable pose-aware multiview stereo depth estimator with parameters $\theta_M$.  The multiview input is
\begin{equation}
    \mathcal{V}_t =
    \left\{(I_{t_i},K_{t_i},T_{t_i}^{w\rightarrow c})\right\}_{i=0}^{N_s},
    \qquad t_0=t,
    \label{eq:mvs_view_set}
\end{equation}
Here $t$ is the target time index for which depth and semantic occupancy are predicted.  The notation $t_0=t$ means that the first element of $\mathcal{V}_t$ is the target, or reference, view.  The remaining elements $t_1,\ldots,t_{N_s}$ are calibrated source views used for multiview matching against the target view. We consider only two views for this study.

In the implementation, $f_{D,\mathrm{MVS}}^{\theta_M}$ is realized by source-specific V-JEPA 2.1 video features, pose-aware projective matching, and a trainable cost-volume regularizer.  At this level, we write it generally as a mapping from posed views to a target-frame dense depth estimate $\hat{D}_t^{\mathrm{MVS}}$ and depth probability tensor $P_t^{D,\mathrm{MVS}}$.

The function $f_S^{\theta_S}$ denotes the semantic scene completion model with trainable SSC parameters $\theta_S$.  In our frozen-backbone setting, the V-JEPA 2.1 encoder weights are fixed, while $\theta_D$, $\theta_M$, and $\theta_S$ are either learnable or frozen based on the variant.  The term $\Phi_t$ denotes the visual context representation extracted from the target observation.  The camera intrinsics $K_t$ and altitude $h_t$ provide geometric metadata for projection and scale conditioning.  The dense depth prediction $\hat{D}_t$ gives the expected metric depth at each image location, while $P_t^D$ is a depth probability tensor used for lifting image features along camera rays.  The output $\hat{Y}_t$ is the predicted semantic occupancy grid.

\subsection{Frozen V-JEPA 2.1 Feature Extraction}
\label{sec:method_vjepa_features}

% For a single RGB image, the implementation routes the image through the video-capable V-JEPA 2.1 code path with a singleton temporal axis, so the output is treated as a spatial patch map for the target view.  For video experiments, the input is a clip with an explicit temporal dimension, and the V-JEPA 2.1 tubelet axis is preserved before the downstream adapter decides whether to concatenate, attend over, or project temporal features.  This keeps the backbone fixed while changing only the neck or task head attached to the extracted representation.

V-JEPA 2.1 is used in two input modes: an RGB/image mode and a video mode. Let $E_{\theta}$ denote the frozen V-JEPA 2.1 encoder~\cite{murlabadia2026vjepa21}.  For the ViT-Gigantic checkpoint used in the experiments, the feature channel dimension is $C=1664$, which is why every spatial token is represented by a 1664-dimensional descriptor.  The model has 48 transformer blocks, indexed from 0 to 47, and a $384\times384$ input with patch size 16 producing a $24\times24$ spatial grid, $384/16=24$.

\paragraph{RGB mode:}

A target image $I_t$ is encoded into one or more spatial feature maps.  We use either the final layer alone or four intermediate layers:
\begin{equation}
    \mathcal{L}_{\mathrm{G}}=\{11,23,37,47\},
    \qquad
    F_t^{(l)} = E_{\theta}^{(l)}(I_t)\in\mathbb{R}^{C\times24\times24},\quad l\in\mathcal{L}_{\mathrm{G}}.
    \label{eq:vjepa_multilayer_features}
\end{equation}
Here, $\mathcal{L}_{\mathrm{G}}$ lists the selected ViT-G layers, $l$ indexes one of those layers, and $F_t^{(l)}(:,u,v)$ is the 1664-dimensional RGB descriptor at spatial grid cell $(u,v)$.
For image-mode depth prediction, the frozen encoder returns image-grid features
without a temporal tubelet axis.  In particular, the final-layer RGB feature map
has the form
\begin{equation}
    F_t^{(47)}\in\mathbb{R}^{1664\times24\times24}.
\end{equation}
A dense linear probe applies a lightweight batch-normalized \(1\times1\)
prediction head to the final frozen feature map, following standard frozen-feature
linear probing practice for dense ViT representations
\cite{murlabadia2026vjepa21,simeoni2025dinov3,facebookresearch_dinov3_linear_head}.
The DPT variant instead consumes selected intermediate feature maps and
reassembles them into a multiscale hierarchy following DPT
\cite{ranftl2021dpt}.

\paragraph{Video mode:}

We form a four-frame clip centered at target frame \(t\):
\begin{equation}
    \begin{gathered}
    X_t =
    [I_{t+\tau_1}, I_{t+\tau_2}, I_{t+\tau_3}, I_{t+\tau_4}]
    \in \mathbb{R}^{3\times4\times384\times384},\\
    [\tau_1,\tau_2,\tau_3,\tau_4]=[-1,0,0,+1].
    \end{gathered}
\end{equation}
The duplicated zero offset places the target frame twice in the clip.  This gives
a target-centered local temporal window while keeping the clip length divisible
by the V-JEPA~2.1 tubelet size.

For V-JEPA~2.1 ViT-Gigantic, the patch size is \(16\), the video tubelet size is
\(2\), and the feature dimension is \(C=1664\).  Therefore, a
\(384\times384\) input produces a \(24\times24\) spatial grid, and a
\(T\)-frame video clip produces \(T'=T/2\) temporal tubelet positions:
\begin{equation}
    G_t^{(l)} = E_{\theta}^{(l)}(X_t)
    \in \mathbb{R}^{1664\times T'\times24\times24}.
    \label{eq:vjepa_video_features}
\end{equation}
For the four-frame clips used here, \(T=4\) and hence \(T'=2\).
Video-mode features contain both spatial locations and temporal tubelet tokens,
so we use lightweight adapters to expose them to dense depth heads.
\paragraph{We tested two types of adapters for video features:}
The first type being \emph{linear probe for video mode} that uses only the final V-JEPA feature tensor \(G_t^{(47)}\). To keep the probe linear while retaining the tubelet information, the temporal tubelet axis is folded into the channel axis before applying the same \(1\times1\) depth-bin head used by the image linear probe:
\begin{equation}
    \begin{gathered}
    G_t^{(47)}
    \in
    \mathbb{R}^{1664\times T'\times24\times24}
    \mapsto
    \widetilde{F}_t
    \in
    \mathbb{R}^{(1664T')\times24\times24},\\
    \widetilde{F}_t[t'C+c,u,v]
    =
    G_t^{(47)}[c,t',u,v],
    \qquad
    0\leq c<1664,\quad 0\leq t'<T'.
    \end{gathered}
    \label{eq:video_linear_probe_fold}
\end{equation}
For \(T=4\), this gives
\begin{equation}
    \widetilde{F}_t
    \in
    \mathbb{R}^{3328\times24\times24}.
\end{equation}
This probe has no spatial decoder, temporal attention, recurrent module, or
backbone finetuning.  It is used as a diagnostic for whether depth-relevant
temporal information is linearly accessible from the frozen final-layer video
features.

The second adapter is the \emph{Dense Temporal Attention} (DTA) adapter.  DTA is
inspired by the attentive probing heads used for V-JEPA~2.1 video
evaluation, where learnable-query cross-attention pools frozen video tokens for classification
\cite{assran2025vjepa2,murlabadia2026vjepa21,facebookresearch_vjepa2}.
Instead of pooling all spatio-temporal tokens into one global classification
vector, DTA applies the same learned-query attention idea locally at every
spatial cell.  For each selected layer
\(l\in\{11,23,37,47\}\), the temporal descriptors at location \((u,v)\) are
\begin{equation}
    S_{t,u,v}^{(l)}
    =
    \left[
    G_t^{(l)}[:,1,u,v],\ldots,G_t^{(l)}[:,T',u,v]
    \right]
    \in
    \mathbb{R}^{T'\times1664}.
\end{equation}
The adapter \(A_l\) attends over this local tubelet sequence and returns one
image-grid feature vector at the same spatial location:
\begin{equation}
    A_l(G_t^{(l)})
    =
    \bar{F}_t^{(l)}
    \in
    \mathbb{R}^{1664\times24\times24}.
\end{equation}
At a single spatial location, the operation can be summarized as
\begin{equation}
    \begin{aligned}
    \mu_t^{(l)}[:,u,v]
    &=
    \frac{1}{T'}
    \sum_{\tau=1}^{T'}
    G_t^{(l)}[:,\tau,u,v],\\
    \bar{F}_t^{(l)}[:,u,v]
    &=
    \mu_t^{(l)}[:,u,v]
    +
    \alpha_l
    \left(
    \mathrm{DTA}_l(S_{t,u,v}^{(l)})
    -
    \mu_t^{(l)}[:,u,v]
    \right),
    \end{aligned}
    \label{eq:dta_residual}
\end{equation}
where \(\mathrm{DTA}_l(\cdot)\) denotes the bottleneck projection,
learned-query multi-head temporal attention, MLP refinement, and expansion back
to 1664 channels.  The residual gate \(\alpha_l\) is initialized near temporal
mean pooling, so training can gradually introduce attention-based temporal
corrections.

The resulting DTA maps
\(\{\bar{F}_t^{(l)}\}_{l\in\{11,23,37,47\}}\) have the same
\(1664\times24\times24\) image-grid form as RGB V-JEPA feature maps.  They can
therefore be passed to the same dense downstream machinery used in image mode,
including DPT-style decoding for depth prediction,  F2D feature prediction, and pose aware multiview cost-volume construction.

\subsection{Depth Estimation}
\label{sec:method_depth_heads}

Depth estimation in this study follows the monocular mapping $f_D^{\theta_D}$ and the pose-aware multiview stereo mapping $f_{D,\mathrm{MVS}}^{\theta_M}$ in Eq.~\eqref{eq:task_functions}.  The monocular heads use a target image, camera intrinsics, and altitude metadata, while the MVS heads use calibrated target/source views to estimate target-frame depth.  In the variants considered here, each depth head predicts ray-wise logits over metric depth bins and converts them to a dense metric depth estimate:
\begin{equation}
    p_{k,u,v}=\operatorname{softmax}_k(z_{k,u,v}),
    \qquad
    \hat{D}_{u,v}=\sum_{k=1}^{K_D}p_{k,u,v}d_k,
    \label{eq:depth_estimate}
\end{equation}
where $K_D=256$ and $d_k$ are metric depth-bin centers.  Thus the depth output is represented consistently as a categorical depth probability tensor and its dense metric estimate.  In the monocular heads the logits $z$ are produced by a linear probe or DPT-style decoder; in the pose-aware MVS heads they are produced by a regularized projective cost volume before the same softmax-based depth-estimation conversion.

\subsubsection{Linear Probe}
\label{sec:method_linear_probe}

The linear probe is the simplest transfer test in the depth study.  It keeps the V-JEPA 2.1 backbone frozen and uses only the learnable head marked in Table~\ref{tab:depth_block_flows}, following standard frozen-feature dense probing practice and the DINOv3 open-source dense-depth linear head used as implementation reference for the RGB case~\cite{simeoni2025dinov3,facebookresearch_dinov3_linear_head}.  Its purpose is diagnostic: if a linear head can recover metric depth, then the frozen representation already exposes monocular depth estimation (MDE) cues in a directly transferable form.

The same diagnostic is applied in RGB and video mode, as summarized in Table~\ref{tab:depth_block_flows}.  In RGB mode, the probe is applied to the final image feature map $F_t^{(47)}$.  In video mode, the final video tensor $G_t^{(47)}$ is converted to the video linear-probe feature $\widetilde{F}_t$ by folding the temporal tubelet axis into the channel axis before the same type of location-wise head is applied.  This video probe therefore tests whether temporal features from V-JEPA 2.1 contain depth cues that are accessible without a nonlinear temporal decoder.

\subsubsection{DPT Depth Decoders}
\label{sec:method_dpt_decoders}

DPT-style decoders are the structured alternatives to the linear probes.  They follow the Dense Prediction Transformer principle of reassembling transformer features into image-like maps and fusing them with convolutional refinement for dense prediction~\cite{ranftl2021dpt}.  Table~\ref{tab:depth_block_flows} gives the variant-level data flow, representative shapes, and learnable blocks; the equations below define only the shared DPT intermediates used by the SFP and FiLM variants.

For the  DPT path, selected V-JEPA 2.1 layers $\mathcal{L}_{\mathrm{G}}=\{11,23,37,47\}$ are reassembled and projected to a common decoder width $C_D=256$:
\begin{equation}
    R_l = \rho_l\left(F_t^{(l)}\right),
    \qquad R_l\in\mathbb{R}^{C_D\times H_l\times W_l},
    \quad l\in\mathcal{L}_{\mathrm{G}},
    \label{eq:dpt_reassembly}
\end{equation}
where $\rho_l$ denotes the DPT reassembly and projection block.  These maps are either fused directly by the  DPT decoder or passed through FiLM conditioning before fusion.

\paragraph{SFP-DPT.}
The Simple Feature Pyramid (SFP) variant tests the final-layer-feature hypothesis for V-JEPA 2.1 transfer.  V-JEPA 2.1 reports strong dense features with deep supervision~\cite{murlabadia2026vjepa21}, so a plausible question is whether the final ViT-G map already carries enough earlier-layer information for depth once it is converted into a multiscale pyramid.  To test this, the SFP-DPT branch uses only the final feature map $F_t^{(47)}$ and constructs the multiscale maps listed in Table~\ref{tab:depth_block_flows}.  The pyramid design is inspired by the Simple Feature Pyramid used with plain ViT backbones in ViTDet~\cite{li2022vitdet}; we cite it as architectural inspiration rather than as an external implementation dependency.
\begin{equation}
    \operatorname{SFP}(F_t^{(47)})=
    \{S_4,S_2,S_1,S_{1/2}\},
    \qquad
    S_s\in\mathbb{R}^{256\times(24s)\times(24s)},
    \quad s\in\{4,2,1,1/2\}.
    \label{eq:sfp}
\end{equation}
The resulting pyramid is decoded by the DPT-style depth head marked in Table~\ref{tab:depth_block_flows} into 256 depth-bin logits.  This variant separates the value of explicit multiscale decoding from the value of using multiple intermediate V-JEPA 2.1 layers.

\paragraph{FiLM-Conditioned DPT for Aerial Depth.}
\label{sec:method_dpt_film}
The FiLM-conditioned DPT variants test whether altitude and camera calibration should modulate the depth decoder in aerial scenes.  This is relevant because UAV altitude and intrinsics affect the mapping from pixels to metric rays, while the frozen V-JEPA 2.1 representation itself is not updated.  The flow and tensor shapes for RGB and video FiLM-DPT variants are listed in Table~\ref{tab:depth_block_flows}; here we define the metadata conditioning applied to the DPT features.

The conditioning input is the normalized metadata vector
\begin{equation}
    m_t=\left[
    \frac{h_t-40}{10},\frac{f_x}{W},\frac{f_y}{H},\frac{c_x}{W}-0.5,\frac{c_y}{H}-0.5
    \right]\in\mathbb{R}^{5},
    \label{eq:metadata_vector}
\end{equation}
where $h_t$ is UAV altitude and $(f_x,f_y,c_x,c_y)$ are camera intrinsics expressed relative to the image size used by the branch.  A small MLP maps $m_t$ to an embedding $e_t\in\mathbb{R}^{128}$.  For each DPT level, learned affine projections produce a scale and shift that modulate the reassembled feature map:
\begin{equation}
    \widetilde{R}_l = R_l\odot\left(1+\gamma_l(e_t)\right)+\beta_l(e_t),
    \label{eq:film}
\end{equation}
where $\gamma_l(e_t)$ and $\beta_l(e_t)$ have the channel dimension of $R_l$ and are broadcast over spatial locations.  Thus FiLM does not change the spatial resolution listed in Table~\ref{tab:depth_block_flows}; it applies a learned, metadata-dependent channel-wise scale and shift before DPT fusion.  The FiLM projections are initialized so that $\gamma_l\approx0$ and $\beta_l\approx0$ at the start of training, making Eq.~\eqref{eq:film} initially reduce to the unconditioned DPT path.  The FiLM-modulated maps $\{\widetilde{R}_l\}$ are then fused by DPT refinement blocks and decoded into 256 depth-bin logits.

For video FiLM-DPT, the DPT inputs are first converted from tubelet-aware video features to target-frame feature maps using Dense Temporal Attention (DTA), as shown in Table~\ref{tab:depth_block_flows}.  At each selected layer and spatial site, DTA attends over the temporal tubelet descriptors and returns a target-frame map:
\begin{equation}
    \bar{F}_{t}^{(l)}(:,u,v)=
    \mu_{t}^{(l)}(:,u,v)
    +\alpha\left(\operatorname{Expand}\left(\operatorname{MLP}\left(\operatorname{MHA}(q,K,V)\right)\right)
    -\mu_{t}^{(l)}(:,u,v)\right),
    \label{eq:dta}
\end{equation}
where $\mu_{t}^{(l)}=\operatorname{mean}_{\tau}G_t^{(l)}(:,\tau,:,:)$ and $\alpha=\sigma(a)$ is initialized to approximately $0.1$.  The resulting maps $\{\bar{F}_{t}^{(l)}\}_{l\in\mathcal{L}_{\mathrm{G}}}$ are passed to the same FiLM-conditioned DPT decoder as the RGB  variant.

\subsubsection{Pose-MVS-FiLM}
\label{sec:method_depth_pose_mvs_film}

Pose-MVS-FiLM is the pose-aware multiview depth branch in Table~\ref{tab:depth_block_flows}.  It keeps the V-JEPA 2.1 backbone frozen and uses calibrated target/source views to construct a depth-indexed cost volume, following the reference-view matching principle used in learned MVS cost-volume methods such as MVSNet~\cite{yao2018mvsnet}.  Let $\mathcal{V}_t=\{(I_i,K_i,T_{t\rightarrow i})\}_{i\in\mathcal{S}_t}$ denote the calibrated source views for target frame $t$.  For target pixel $\mathbf{u}=(u,v,1)^\top$ and metric depth-bin center $d_k$, the target-frame 3D point and source-view projection are
\begin{equation}
    \mathbf{x}_{t,k,u,v}=d_k K_t^{-1}\mathbf{u},
    \qquad
    \mathbf{q}_{i,k,u,v}=\pi\!\left(K_i T_{t\rightarrow i}
    \begin{bmatrix}\mathbf{x}_{t,k,u,v}\\1\end{bmatrix}\right),
    \label{eq:mvs_projection}
\end{equation}
where $\pi(\cdot)$ is perspective projection.  Let $A_t$ and $A_i$ denote target/source feature maps after the video-feature adaptation shown in Table~\ref{tab:depth_block_flows}.  Source features are sampled at the projected locations, compared with the target feature, and aggregated over source views into a depth-indexed cost volume,
\begin{equation}
    \widetilde{A}_{i,k,u,v}=\operatorname{sample}\left(A_i,\mathbf{q}_{i,k,u,v}\right),
    \qquad
    C_{t,k,u,v}=\operatorname{Agg}_{i\in\mathcal{S}_t}
    \operatorname{corr}\left(A_t(:,u,v),\widetilde{A}_{i,k,u,v}\right).
    \label{eq:mvs_cost_volume}
\end{equation}
The cost volume is regularized by a 3D CNN and mapped to FiLM-conditioned target-frame depth logits,
\begin{equation}
    \begin{gathered}
    Z_{t}^{\mathrm{MVS}}=\phi_{\mathrm{logit}}\!\left(\psi_{3\mathrm{D}}(C_t),e_t\right),\\
    P_{t}^{D,\mathrm{MVS}}=\operatorname{softmax}_k Z_t^{\mathrm{MVS}},
    \qquad
    \hat{D}_{t,u,v}^{\mathrm{MVS}}=\sum_{k=1}^{K_D}P_{t,k,u,v}^{D,\mathrm{MVS}}d_k .
    \end{gathered}
    \label{eq:mvs_depth_estimate}
\end{equation}
This branch uses the same $K_D=256$ metric depth-bin centers and target-frame depth supervision as Eq.~\eqref{eq:depth_estimate}.  CVP-MVSNet and CasMVSNet are treated as related cascaded MVS literature where cited elsewhere; the implementation described here is a single cost-volume branch rather than a cascade of those methods.

\subsubsection{Altitude-Interpolation Depth Evaluation}
\label{sec:method_altitude_interpolation_depth}

The standard OccuFly dataset split uses scenes 01--05 for training, scenes 06--07 for validation, and scenes 08--09 for testing, with altitudes 30 m, 40 m, and 50 m.  We also include an altitude-interpolation protocol in which training uses 30 m and 50 m samples from scenes 01--08, validation uses 40 m samples from scenes 01--04, and testing uses 40 m samples from scenes 05--08:
\begin{align}
    \mathcal{D}_{\mathrm{train}} & = \{s_t: h_t\in\{30,50\},\ \operatorname{scene}(t)\in\{01,\ldots,08\}\}, \\
    \mathcal{D}_{\mathrm{val}} & \subset \{s_t: h_t=40,\ \operatorname{scene}(t)\in\{01,02,03,04\}\}, \\
    \mathcal{D}_{\mathrm{test}} & \subset \{s_t: h_t=40,\ \operatorname{scene}(t)\in\{05,06,07,08\}\}.
\end{align}
This split is a scale-generalization stress test: it reports model depth prediction errors at the unseen middle altitude.  It is especially relevant for FiLM-conditioned depth heads, because their metadata pathway is intended to use UAV altitude at inference time; performance at 40 m after training on 30 m and 50 m tests whether that conditioning supports interpolation across altitude rather than only fitting observed flight heights.

\subsubsection{Losses}
\label{sec:method_depth_losses}

The resulting depth map is resized to the supervision resolution and trained with a valid-pixel scale-invariant logarithmic loss.  Let $\Omega_D$ be the set of valid supervised pixels after resizing, $N=|\Omega_D|$, and $i\in\Omega_D$ index one valid pixel.  For predicted depth $\hat{D}_i$, ground-truth OccuFly depth $D_i$, and log-depth residual $g_i=\log \hat{D}_i-\log D_i$, the loss is
\begin{equation}
    \mathcal{L}_{\mathrm{sig}} =
    \sqrt{\frac{1}{N}\sum_{i\in\Omega_D}g_i^2
    -\lambda_{\mathrm{si}}\left(\frac{1}{N}\sum_{i\in\Omega_D}g_i\right)^2 + \epsilon},
    \label{eq:sigloss}
\end{equation}
where $\lambda_{\mathrm{si}}$ controls the scale-invariant correction term and $\epsilon$ is a small positive constant for numerical stability.  The term inside the square root is the scale-invariant log-depth objective of Eigen et al.~\cite{eigen2014depth} when $\lambda_{\mathrm{si}}=0.5$; the square root and $\epsilon$ give the numerically stabilized SiLog-style form used here.  We use this loss because aerial metric depth contains unavoidable global-scale ambiguity, while the altitude/intrinsics conditioning experiments test whether that ambiguity can be reduced by physically meaningful metadata.

\subsubsection{Evaluation Metrics}
\label{sec:method_depth_metrics}

Depth models are evaluated only over valid pixels.  The manuscript uses root mean squared error (RMSE), absolute relative error (AbsRel), and log-RMSE:
\begin{equation}
    \operatorname{RMSE}=\sqrt{\frac{1}{N}\sum_{i\in\Omega_D}(\hat{D}_i-D_i)^2},
    \qquad
    \operatorname{AbsRel}=\frac{1}{N}\sum_{i\in\Omega_D}\frac{|\hat{D}_i-D_i|}{D_i},
\end{equation}
\begin{equation}
    \operatorname{LogRMSE}=\sqrt{\frac{1}{N}\sum_{i\in\Omega_D}(\log\hat{D}_i-\log D_i)^2}.
\end{equation}
For video-depth runs, the evaluation script also supports MAE, squared-relative error, and threshold accuracies $\delta_1,\delta_2,\delta_3$ when enabled.

\label{sec:method_ssc}

The SSC benchmark isolates two factors that are otherwise coupled in end-to-end completion systems.  The image-context pathway contributes semantic visual features, while the geometry pathway contributes monocular depth, depth distributions, or pose-aware MVS priors.  Both pathways are then lifted into a common 3D representation before fusion and semantic occupancy prediction.

Semantic scene completion (SSC) is evaluated after depth estimation because the depth branches provide geometry priors for downstream 3D semantic occupancy.  The SSC experiments test whether those priors, together with the corresponding image-context or F2D features, transfer into a 3D completion task.  The purpose is not to introduce a completely new SSC architecture.  Instead, we use published SSC designs whose image-context and geometry pathways are exposed enough to support controlled feature-transfer studies.

CGFormer and FoundationSSC are selected consciously even though their published forms use stereo-derived geometry priors rather than the monocular MDE or pose-aware MVS depth estimators targeted in this chapter.  The reason is methodological: both expose a useful separation between image-context information and geometry information.  CGFormer combines an image encoder, depth-context components including depth-aware view transformation, CGVT, a 3D local-global encoder, and a decoding head~\cite{yu2024cgformer}.  FoundationSSC is a dual-decoupling framework with a foundation encoder, decoupled semantic-context and geometric pathways, hybrid view transformation, axis-aware fusion, and a decoding head~\cite{chen2025foundationssc}.  We adapt these published designs for controlled evaluation.

\subsubsection{CGFormer Variant: Frozen Depth Prior Substitution}
\label{sec:method_cgformer}

The modification is to use precomputed depth maps from frozen pretrained depth heads as replacement geometry priors for CGFormer's original stereo-depth or depth-map input slot.  The depth-prior sources considered are from Depth Anything V2 fine tuned on Occufly (cite occufly dataset) and V-JEPA 2.1 depth head DPT-FiLM trained on Occufly.
SSC metrics like occupied mean intersection over union (mIoU) for measure of sematic class matching and intersection over union (IoU) for measure of occupied occupany are reported as a preliminary comparison.

\subsubsection{FoundationSSC Variant}
\label{sec:method_foundationssc_hybrid}

FoundationSSC is used as a stronger published follow-up baseline because it explicitly decouples semantic-context and geometric information at both the source and pathway levels~\cite{chen2025foundationssc}.  In its published implementation, a frozen FoundationStereo encoder provides image-context features, cost-volume geometry features, and a dense depth map.  Compared with CGFormer, FoundationSSC is reported in the published comparison to improve on SemanticKITTI and SSCBench-KITTI-360, with the gains attributed to the decoupled foundation encoder-pathways, learned disparity-to-depth volume mapping, hybrid view transformation, and axis-aware fusion~\cite{chen2025foundationssc,yu2024cgformer}.  We therefore use it as a suitable architecture for ablation studies.
